# CMSの公開反映・追加不具合の確認

確認日：2026年10月31日（日本時間）。Cloudflare Pages移行後のメンテナンスOFFと、その他の更新処理を確認しました。

## メンテナンスOFFについて確認できた事実

- `897219b`：CMSが公開URLを`https://yusuke-official-website.pages.dev/`へ保存。
- `07fc58e`：CMSが`maintenanceEnabled: false`を保存。利用者が示したCloudflare ProductionのSourceも同じコミット。
- 最新CMS設定を使ったCloudflareビルドでは、公開JSONはOFF、TOPには通常のHEROがあり、12ページ・69ファイルの静的検証が成功。
- CMS項目名の不一致、OFFを無視する分岐、JavaScriptのメンテナンス強制転送は見つかっていない。
- その後、利用者からホームを開いているとの回答があった。当時の閲覧URL・実レスポンスは取得できず、キャッシュや過去のデプロイURLを一次原因と断定していない。

CMSの保存成功と、公開処理の完了、既に開いているタブの再読み込みは別の状態です。固定URLを使い、古い個別デプロイURL・専用`/maintenance`ページと区別します。

## 追加した対策・修正

| 対象 | 修正内容 |
| --- | --- |
| CloudflareのHTML | TOP・`.html`形式・拡張子なし形式のすべてに再検証するCache-Controlを指定。 |
| 公開JSON | `/data/*`を`no-store`にする。長期キャッシュは内容ハッシュ付き画像だけに限定。 |
| 公開版の診断 | `data/publication.json`へ公開コミットID`sourceCommit`を追加。ビルドログにCMSのメンテナンス設定・生成モードを明示。CIが値を提供しないローカルビルドは`null`。不正な環境変数値は公開しない。 |
| スポンサー・応援メッセージの削除 | 最新JSONが0件なのに古いHTMLの掲載が残る条件を修正。正常な空配列なら古い項目を消して0件表示へ更新。 |
| 上記一覧の通信・データ取得失敗 | 取得失敗を0件扱いにせず、元の表示を保持して最新情報の確認失敗を案内。 |

利用者が保存したメンテナンスOFF・公開URL・Facebook・写真の設定は保持しています。今回の作業でメンテナンスONへ戻していません。

## 未確認の範囲

この環境からCloudflareの公開URLへのHTTPS接続はCONNECT制限のため取得できていません。実配信のHTTPヘッダー、CDNキャッシュ設定、実CMS画面からの保存、実機Safari・Edge、Googleフォームの実送信・所有者受信は未確認です。ローカルブラウザは全応答をローカルに置き換えており、外部送信はしていません。

新しいコミットのCloudflareデプロイ成功後、固定URLを開き直して確認します。公開版の照合は`/data/publication.json`の`sourceCommit`・`maintenanceEnabled`・`contentId`とCloudflare Deploymentsを使います。詳細は[CMS反映の診断](CMS_DIAGNOSIS.md)を参照してください。
