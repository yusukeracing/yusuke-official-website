# コードを開かずに更新する

[Pages CMS の管理画面](https://app.pagescms.org/)から、活動報告・ニュース・写真・プロフィール・SNSをフォーム入力で更新できます。このリポジトリには編集フォームの設定 `.pages.yml` を用意しています。公開サイトに管理者用リンクや独自のログイン画面を設ける必要はありません。

## 最初の1回だけ行う接続

1. [Pages CMS](https://app.pagescms.org/)を開き、サイトを管理するGitHubアカウントでサインインします。
2. GitHub Appの接続先に `yusukeracing/yusuke-official-website` を選びます。他のリポジトリへのアクセスは不要です。
3. リポジトリを開き、編集するブランチに **`main`** を選びます。
4. 「活動報告・ニュース」「プロフィール・ストーリー」「サイト設定・SNS」「ギャラリー」などのフォームが表示されれば準備完了です。

GitHubアカウントでのサインインとAppの接続は、アカウント所有者がブラウザで行います。設定ファイルの配置だけでは、アカウント接続や権限付与は完了しません。Pages CMS側の画面・プランによって表示名が異なる場合があります。

## 活動報告・ニュースを投稿する

1. 「活動報告・ニュース」を開き、「記事」に項目を追加します。
2. 公開日、カテゴリ、タイトル、本文を入力します。活動報告ではカテゴリに **「活動報告」** を選びます。
3. 写真を付ける場合は画像をアップロードして選択します。写真なしでも掲載できます。
4. 他のページへ案内する場合だけ「関連記事URL」を入力します。サイト内で本文を読ませる場合は空欄にします。
5. 内容を確認し、正式な記事は「仮原稿として表示する」をOFFにして保存します。
6. `main` への保存をきっかけに、GitHub Actionsが検証・公開を自動実行します。完了後、活動報告ページとTOPで表示を確認します。

HTML・JSON・コードを編集する必要はありません。本文は普通の文章で入力し、空行で段落を分けます。記事は日付の新しい順に表示し、TOPには最新3件を掲載します。カテゴリは「活動報告」「レース」「お知らせ」「メディア」から選べます。

掲載済みの「全日本ロードレース初参戦シーズンを終えて」は、公開用に「仮原稿として表示する」をOFFにしています。本文や表示設定はCMSから変更できます。この設定は**表示上の目印**であり、非公開の下書き機能ではありません。ONの原稿もサイト・公開JSON・Git履歴から読めます。公開前の機密原稿は別の場所で管理してください。

保存直後に切り替わるとは限りません。[GitHub Actions](https://github.com/yusukeracing/yusuke-official-website/actions)で対象更新の公開処理が成功しているか確認してください。失敗した場合は直前の公開版が続けて表示されます。公開完了後も古い画面の場合はページを再読み込みします。

### レビューしてから公開する場合

複数人で編集する場合や `main` がPR必須に保護されている場合は、CMSで `content` などの編集ブランチを選び、保存 → GitHubでPull Request → 確認して `main` にマージ、の順にします。編集ブランチにも `.pages.yml` が必要です。この設定はブランチを自動作成したり、GitHubの保護ルールを変更したりしません。

## プロフィール下のヒトコトを変える

「プロフィール・ストーリー」の **「池田優介からのヒトコト」** に本文を入力し、保存します。TOPのプロフィール下とプロフィールページに同じ文章が表示されます。本人からのファンへのメッセージ用です。

掲載中のヒトコトは公開用に仮原稿表示をOFFにしています。必要な場合は「ヒトコトを仮原稿として表示する」をONにできます。このスイッチも非公開設定ではありません。

## メンテナンス画面に切り替える

1. 「サイト設定・SNS」を開きます。
2. 必要に応じて「メンテナンス中の案内文」を入力します。
3. **「メンテナンス画面を表示する」をON**にして保存します。
4. GitHub Actionsの公開完了後、TOPだけでなくプロフィールや活動報告のURLもメンテナンス案内になります。
5. 再開時は同じスイッチを**OFF**にして保存し、公開完了を確認します。

通常はOFFです。サーバーの停止、`404.html` の手動差し替え、コードの編集は不要です。公開ビルドでHTML自体を置き換えるため、JavaScriptを無効にした閲覧や各ページへの直接アクセスにも対応します。写真・CSS・SNSリンクは引き続き配信します。

`404.html` は存在しないURLへの案内です。メンテナンスON時はこの404案内もメンテナンス文面になります。既存ページはHTTP 200、存在しないURLはHTTP 404のままで、GitHub Pagesではこの設定からHTTP 503を返すことはできません。全ページに `noindex` を付け、サイトマップから記事URLを一時的に外します。解除後のビルドで通常の検索設定に戻ります。

切り替えは次の公開処理の完了時に反映します。すでに開いているタブや外部キャッシュを即座に切り替える機能ではありません。ファイルや公開JSONを非公開にするアクセス制限でもありません。GitHub Pages自体の停止中はメンテナンス画面も配信できません。

## 写真の差し替え

1. 各編集フォームの画像欄から、掲載許可のある写真をアップロードして選択します。保存先は `assets/images/uploads/` です。
2. 写真の説明欄には、実際に写っている場面を入力します。
3. 保存・公開後、PCとスマートフォンで表示を確認します。

写真はCMSの設定が優先されます。HTMLの `img src` だけを変更すると、読み込み後にCMSの設定へ戻る箇所があります。

| 掲載位置 | CMSの設定項目 | 現在の写真 |
| --- | --- | --- |
| TOPのメイン写真 | サイト設定・SNS → HERO・PC用写真 | `yusuke.hero_01.jpg` |
| CURRENT SEASON | サイト設定・SNS → 各セクションの写真 → CURRENT SEASON | `yusuke.hero_02.jpg` |
| プロフィール | プロフィール・ストーリー → プロフィール写真 | `yusuke.hero_03.jpg` |
| PHOTO STORYの1枚目 | プロフィール・ストーリー → フォトストーリー → 1件目 → 写真 | `yusuke.hero_04.jpg` |

`yusuke.hero_04` はファイル名です。TOPのメイン写真を変える場合は「HERO・PC用写真」を変更します。`xxx` を含む画像名は未設定の目印なので、実画像には別の名前を付けます。

ギャラリーでは縦長・横長写真をそれぞれの元の比率で全体表示します。「PC用写真の幅・高さ」などの任意欄には表示枠のサイズではなく、画像ファイルの実際のピクセル数を入力します。例：1566×1044pxの写真は幅1566・高さ1044です。未確認なら空欄でもかまいません。

画像パスは `assets/images/uploads/写真.webp` のような相対パスを使います。先頭を `/assets/` にするとGitHub Pagesのプロジェクト公開パスから外れます。CMSのアップロードは相対パスに設定済みです。

サイズの目安はHERO横1600px・150〜300KB、一般写真80〜200KB、スマートフォン横640〜800pxです。巨大な原本はそのまま掲載せず、構図と画質を保って縮小します。原本と撮影者の掲載許可は別途保管します。

## SNSを変える

「サイト設定・SNS」→「SNSリンク」で、対象サービスの本人の**プロフィールURL**を入力します。InstagramとXの `@アカウント名` はURLから自動更新します。ヘッダー・フッター・SNS欄に同じリンクを使うため、HTMLを別々に直す必要はありません。

現在の登録先はInstagram `@yusukeikedaikeda`、X `@yusukeikeda1026` です。Facebookは本人のURLが未登録なので、**「アカウント準備中」と表示し、Facebookのトップページにリンク**しています。後からFacebookのプロフィールURLを入力して保存すると、本人のページへ切り替わります。

`handle` はURLが未入力の場合の補助項目です。Instagram・XではURLと表示名が食い違う場合はURLが優先されます。投稿・共有画面のURLを指定しないでください。不正な接続先は採用しません。未設定のInstagram・Xは公開リンクを表示しません。

## スポンサー企業・応援メッセージを掲載する

「スポンサー」に登録すると、企業一覧・TOPなどに反映されます。「応援メッセージ（公開用）」には、本人からのヒトコトとは別に、ファンからの公開許可済みの文章を登録します。

Google Formsから受け取った場合も、掲載同意と公開してよい表示名を確認し、承認済みの文面だけをCMSへ転記してください。問い合わせ原文・メール・電話・非公開投稿はFormsや権限を限定したSheetsで管理し、公開JSONやGitに入れません。Formsの回答を自動で公開する機能はありません。

## Google Forms・検索・GA4

お問い合わせのGoogle Formsは登録済みです。変更する場合はGoogle Formsの埋め込みHTMLの `src` にあるURLだけを「Google Forms 埋め込みURL」へ、`height` を表示高さへ入力します。HTML一式は貼りません。回答受付・閲覧範囲・受信はフォーム所有者側で確認します。

公開URLを変更する場合は「公開URL」に末尾 `/` 付きのHTTPS URLを設定し、保存・公開します。ビルドがcanonical・OGP・サイトマップを更新します。独自ドメインのDNSやGitHub側の設定は別途必要です。

GA4を使用する場合は公開用の測定ID `G-…` を入力します。未設定の `xxx` の間は計測しません。API秘密鍵やGoogleのパスワードは入力しません。

## 設定と権限の確認

設定はPages CMS公式の構成に合わせています。実アカウント接続・画像アップロード・保存から公開までの一連の操作は、アカウント所有者による初回接続後に確認してください。GitHubとCMSは必要な人だけがアクセスできるようにし、アカウントの2FAなどを設定します。

秘密情報、問い合わせの回答データ、`.env`、GitHub Token、外部サービスの秘密鍵は、CMSにもリポジトリにも入力しないでください。
