# Pages CMS での更新

このサイトは HTML / CSS / Vanilla JavaScript の静的サイトです。公開サイトに独自の管理画面、ログイン機能、PHP、データベースはありません。ルートの `.pages.yml` に、Pages CMS が読み込む編集フォームを用意しています。

## 初回接続

1. この変更を対象の GitHub リポジトリへ反映します。
2. [Pages CMS](https://pagescms.org/) から管理サービスにサインインし、GitHub アカウントで認証します。
3. GitHub App が要求する権限を確認し、対象を `yusukeracing/yusuke-official-website` のみに限定して接続します。編集者は必要な人だけに限定してください。
4. リポジトリと編集ブランチを選択します。選択ブランチにも `.pages.yml` が必要です。
5. 「サイト設定・SNS」「プロフィール・ストーリー」「レース予定・結果」「ニュース」「スポンサー」「ギャラリー」の編集項目が表示されることを確認します。
6. まず小さな編集を保存し、GitHub の差分を確認します。ローカルで表示を確認したあと、レビューして公開ブランチに反映します。

このリポジトリに設定ファイルを置くだけでは、GitHub App のインストール、Pages CMS のアカウント接続、編集者の権限設定は行われません。これらの操作はアカウント所有者が行います。Pages CMS 側の最新UIやプランに応じて名称が異なる場合があります。

## 推奨する更新の流れ

`content` ブランチで CMS 編集 → GitHub で Pull Request → 内容・画像・リンクをレビュー → `main` にマージ → GitHub Pages で公開、という運用を推奨します。

最初に `main` から `content` ブランチを作成し、Pages CMS でそのブランチを選んでください。CMS は選択ブランチにコミットします。この設定ファイルは自動でブランチを作成したり、PRを作成したり、`main` を保護したりしません。レビュー後は `main` の更新を `content` に取り込み、古い内容を上書きしないようにします。

GitHub Ruleset では PR 必須、必要なチェック、force push とブランチ削除の禁止を検討してください。署名必須などは CMS / GitHub App のコミット方式との互換性を確認してから有効化します。GitHub と CMS に関係するアカウントでは 2FA、可能ならパスキーを使用し、復旧コードを安全に保管します。

## 写真の差し替え

写真は生成していません。`xxx-hero-01.webp` などの名前は差し替え位置を示すものです。サイト上の写真枠と HTML の `PHOTO SLOT` コメントを照合できます。

写真の設定は JSON / Pages CMS が優先されます。HTML の `img src` だけを変更すると、データ読み込み後に CMS の設定へ置き換わる箇所があります。特に PHOTO STORY は `data/profile.json` の `stories` から再描画するため、必ず対応する `image` も更新してください。

現在登録されている写真の対応：

| 掲載位置 | 設定項目 | 写真 |
| --- | --- | --- |
| TOPのメイン写真 | `data/site.json` → `heroImage` | `yusuke.hero_01.jpg` |
| CURRENT SEASON | `data/site.json` → `photos.currentRace` | `yusuke.hero_02.jpg` |
| プロフィール | `data/profile.json` → `portraitImage` | `yusuke.hero_03.jpg` |
| PHOTO STORYの1枚目 | `data/profile.json` → `stories` の1件目 → `image` | `yusuke.hero_04.jpg` |

ファイルは `assets/images/` にあります。`yusuke.hero_04` はファイル名であり、TOPのメイン写真への自動割り当てではありません。TOPで使う写真を変更するときは `heroImage` を変更します。

1. 使用許可のある実際の写真を、WebP または AVIF に変換します。写真原本は別途バックアップします。
2. Pages CMS のメディアからアップロードします。保存先は `assets/images/uploads/` です。
3. 対象フォームの写真欄でアップロードしたファイルを選択し、保存します。
4. 画像の説明欄には、実際に写っている場面を短く記述してください。ファイル名や `xxx` のまま公開しないようにします。
5. スマートフォンの構図が必要な場合はモバイル用写真も選択し、PCと両方で確認します。
6. 「サイト設定・SNS」で HERO写真の説明、CURRENT SEASON・ピット・レース写真、SNS共有用OGP画像も設定できます。OGPは推奨1200×630pxです。

ギャラリーは写真の項目を複数追加できるリストです。各項目で画像と説明を登録し、並べ替えられます。初期12枠は `xxx` の差し替え枠です。写真のない枠は実際の写真として扱わないでください。

ギャラリーの写真は、縦長・横長それぞれの元の縦横比で全体を表示します。写真を固定の枠に切り抜くことはせず、PCでは段組み、スマートフォンでは1列に配置します。CMSで指定した写真の順番は維持します。

「PC用写真の幅・高さ」「スマートフォン用写真の幅・高さ」には、画像ファイルの実際のピクセル数を任意で登録できます。例：横1566px・縦1044pxの画像は `width: 1566`、`height: 1044` です。写真を入れ替えた場合は値も更新してください。PC用とスマートフォン用に同じ画像を選んだ場合は、両方に同じ数値を入れます。登録すると画像が読み込まれる前から正しい比率の領域を確保できます。空欄でも読み込み後に画像本来の比率で表示します。表示したい枠の大きさや、未確認の寸法は入力しないでください。

画像パスは `assets/images/uploads/写真.webp` のような**相対パス**で保存します。先頭を `/assets/` にすると GitHub Pages のプロジェクト公開パスから外れるため避けてください。CMS の `media.output` はこのため相対パスにしています。

サイズの目安は HERO 1600px・150〜300KB、タブレット1024px、モバイル640〜800px、一般写真80〜200KB、サムネイル30〜100KBです。HERO以外は遅延読み込みする構成です。4Kの原本をそのままアップロードせず、構図と画質を確認して縮小します。

## 外部サービスを設定する

### SNS

`socials` の各 `url` と `handle` を、本人の公開アカウントへ変更します。初期値 `https://instagram.com/xxx`、`https://x.com/xxx`、`https://facebook.com/xxx` は未設定を示します。実在の本人アカウントだと解釈しないでください。

### Google Forms

Google Forms でフォームを作成し、「送信」から埋め込みHTMLを取得します。`iframe` の `src` のURLだけを `googleFormUrl` に保存します。`https://docs.google.com/forms/.../viewform?embedded=true` 形式を使います。HTML一式は貼り付けません。未設定は `xxx` です。

フォームではお問い合わせ種類（スポンサー／取材・メディア／イベント／応援／その他）、氏名、会社名、メール、電話、本文などを作成し、必要な項目だけを必須にします。個人情報の利用目的や管理方法をフォームに記載してください。Google Forms の回答画面、またはGoogle Sheets連携で管理します。回答用フォームは通常の利用者が使える公開設定にし、回答一覧・連携シートの閲覧権限は担当者だけに限定します。実際にテスト回答を送信し、受信とフォームの高さを確認してください。

### GA4

公開用の測定ID（`G-...`）を `ga4Id` に入力します。未設定は `xxx` で、仮IDに計測を送らないようにします。APIキーやサービスアカウントの秘密鍵は不要です。設定後に GA4 のリアルタイム／DebugView で、ページ表示、スポンサー、支援、SNS、問い合わせのイベントを確認します。プライバシーの説明や同意の要否は運用地域・実際の計測設定に合わせて整備してください。

### URL・検索設定

独自ドメインを利用する場合は `site.url` を末尾 `/` 付きの正規URLへ変更します。各HTMLの canonical / OGP、`sitemap.xml`、`robots.txt` も同じ公開URLにそろえます。`site.url` の編集だけでは静的HTMLやXMLのURLは一括書き換わりません。独自ドメインの DNS、GitHub Pages Custom Domain、Enforce HTTPS、Search Console の所有権確認はサービス側で設定します。
