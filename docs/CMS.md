# Pages CMSで写真付きの記事を更新する

確認日：2026-10-30（日本時間）。このサイトは [Pages CMS](https://app.pagescms.org/)から編集し、GitHubへJSONと画像を保存して公開する構成です。公開サイトに管理者用のパスワードやAPIトークンを置く必要はありません。

今回の変更では、サムネイルに加えて本文中へ文章と写真を好きな順で追加できるようにしています。記事一覧から記事ごとの詳細ページへ移動できます。

## 接続先を確認する

1. Pages CMSへ、サイトを管理するGitHubアカウントでサインインします。
2. リポジトリは **`yusukeracing/yusuke-official-website`**、編集ブランチは **`main`** を選びます。
3. 「活動報告・ニュース」「サイト設定・SNS」などの編集フォームが表示されることを確認します。
4. GitHub Appを接続し直す場合は、このリポジトリだけにアクセスを許可します。パスワードやトークンを記事・サイト設定へ入力しないでください。

履歴にはPages CMS経由と記録された保存コミットがあります。ただし今回、こちらから実アカウントへログインして操作したわけではありません。別端末・別編集者での初回認証は、その利用者がブラウザで行います。CMSの画面上の名称は利用する版によって多少異なります。

`main`がPR必須に保護されている運用では、編集用ブランチを選び、保存後にPull Requestを作って`main`へマージします。編集用ブランチへ保存しただけでは本番へ公開されません。

## 新しい記事を作る

1. 「活動報告・ニュース」を開き、「記事」に項目を追加します。
2. **「記事URLの名前」**へ、半角小文字の英数字とハイフンで一意の名前を入力します。例：`sugo-report-2026`。同名を別記事に使わず、公開後は変更しません。
3. 公開日、カテゴリ、タイトルを入力します。活動報告の場合はカテゴリに「活動報告」を選びます。
4. **「冒頭の本文」**に文章を入力します。空行で段落を分けます。HTMLタグは不要です。
5. サムネイルを使う場合は「サムネイル写真」を選択し、写真の代替テキストを入力します。説明・撮影者クレジットも必要に応じて入力します。写真なしの記事も作れます。
6. 下記の方法で、本文の続きや写真を追加します。
7. 正式掲載する場合は「サイトへ掲載する」をONにし、「仮原稿として表示する」はOFFにします。
8. 内容を確認して保存します。保存後は、変更内容がGitHubへ記録され、公開処理が成功したことを確認します。

公開日は表示と並べ替えに使う日付です。未来の日付を入力しても予約公開にはならず、「サイトへ掲載する」がONなら次の公開処理で掲載します。

上の例の記事詳細URLは、公開サイトの末尾に **`article-sugo-report-2026.html`** を付けたものです。ファイルを手作業で作成する必要はありません。TOPには日付が新しい記事を最大3件表示し、活動報告一覧からも詳細へ移動できます。「関連記事URL」は別の参考ページへ案内する任意欄で、記事詳細の生成とは別です。

## 本文中に複数写真を入れる

「本文の文章・写真（順番に追加）」へ、必要な数の項目を追加します。

| 追加する内容 | 「種類」で選ぶ値 | 入力する欄 |
| --- | --- | --- |
| 続きの文章 | 文章 | 文章。空行で段落を分けられます。 |
| 写真 | 写真 | 写真、写真の代替テキスト、任意の説明・撮影者クレジット。 |

例えば **文章 → 写真 → 文章 → 写真** の順に並べると、記事詳細でもその順に表示します。写真を複数追加するために、本文へ`<img>`やURLを貼り付ける必要はありません。

代替テキストは「コーナーを走るゼッケン29のマシン」など、実際に写っている内容を短く記述します。説明文には場面や撮影者クレジットを記載できます。確認できない大会名・順位・撮影者名は補完しないでください。

写真を選んだ項目で代替テキストが空欄だったり、記事URLの名前が重複したりすると、公開ビルドがエラーになります。CMSで保存できた場合でも、公開成功とは別なのでActionsを確認します。

## 写真のアップロード先と表示先

写真管理のルートは **`assets/images`** です。既存の`yusuke.gallery_09.jpg`などもここから選択できます。新しい写真は同じ管理領域へアップロードし、整理する場合は`uploads`サブフォルダを使います。

| 段階 | 保存・参照するもの |
| --- | --- |
| CMSの写真管理 | `assets/images`とそのサブフォルダ。 |
| Gitに保存される原画像 | 例：`assets/images/uploads/sugo-2026.jpg`。元画像を保持します。 |
| CMSが記事へ保存する値 | 同じ相対パス。`data/news.json`のサムネイル・本文写真欄に保存します。 |
| 公開時の配信用画像 | ビルドが生成する`assets/optimized/`配下の画像。 |
| 公開HTML・公開用JSON | ビルドで同じ配信用画像のパスへ同期します。 |

`assets/optimized/`は自動生成先です。CMSの保存先として手入力しません。ファイル名を変えて同じ原画像を何度も複製する必要もありません。原画像と配信用画像の対応は公開成果物の画像マニフェストで確認できます。

ファイル名には、できれば半角英数字・ハイフン・アンダースコアを使います。大文字・小文字、拡張子は区別されます。保存値は`assets/images/...`のような相対パスで、先頭に`/`を付けません。これによりGitHub Pagesの`/yusuke-official-website/`配信にも対応します。

## 記事を編集・写真を差し替える

1. 編集したい記事を開きます。既存の「記事URLの名前」は維持します。
2. タイトル・公開日・冒頭本文・各本文項目を編集します。
3. 写真を差し替える場合は画像選択欄で選び直し、代替テキストと説明も新しい写真に合わせます。
4. 本文項目の並べ替え・追加・削除を行い、保存します。
5. 公開成功後、一覧のサムネイルと記事詳細の両方を開きます。スマートフォンでも写真全体、説明、段落、表示順を確認します。

画像をアップロードしただけでは、記事やトップ写真へ自動で割り当てられません。画像を使う欄でもそのファイルを選び、対象コンテンツを保存します。

## 掲載を外す・記事を削除する

- **一時的に掲載を外す**：「サイトへ掲載する」をOFFにして保存します。公開処理後、公開用JSON・記事一覧・記事詳細・サイトマップから除外します。
- **記事を削除する**：「記事」リストから対象項目を削除して保存します。公開ビルドは成果物を作り直すため、削除した記事の詳細ファイルも次の公開から外れます。
- **再掲載する**：内容を確認し、「サイトへ掲載する」をONにして保存・公開します。

このリポジトリは公開GitHubです。掲載OFFの記事でも、原データや過去のコミットをGitHubから読めます。**秘密の下書き機能ではありません。** 非公開にしたい原稿、問い合わせ回答、個人情報は別のアクセス制限された場所へ保存してください。「仮原稿として表示する」は表示上の目印で、非公開設定ではありません。

写真ファイルの削除は記事の削除と別です。他の記事・TOP・ギャラリーで使われていないことを確認してから行います。削除してもGit履歴、閲覧者の保存済みコピー、外部キャッシュから直ちに消えるとは限りません。

## 保存後の反映を確認する

保存と公開は、次の段階に分かれています。

1. **CMSで保存中**：CMSの処理が終わるまで待ちます。画面をすぐ閉じず、CMSが示す成功またはエラーを確認します。
2. **GitHubへ保存済み**：`main`の履歴に新しいコミットがあり、対象ファイルの差分に意図した変更が含まれるか確認します。
3. **公開処理中**：[GitHub Actions](https://github.com/yusukeracing/yusuke-official-website/actions)で、そのコミットの処理が実行待ち・実行中なら公開反映を待ちます。
4. **公開成功**：対象処理が成功したら、一覧・詳細・画像を確認します。既に開いていたタブは再読み込みします。
5. **公開失敗**：エラーを直して再保存します。公開が失敗した場合、公開サイトは直前の版を表示し続けます。

連続して保存すると、古い公開処理が取り消されて最新の処理へまとめられる場合があります。古い処理の「Cancelled」だけを見て保存失敗と判断せず、**最新コミットの結果**を確認します。

Pages CMSは外部サービスなので、このリポジトリからその保存ボタン・認証・保存中表示を変更できません。CMSの表示と、GitHubの差分・Actions・公開版を組み合わせて切り分けます。詳しくは[CMS反映の診断記録](CMS_DIAGNOSIS.md)を参照してください。

## トップ写真を変更する

「サイト設定・SNS」→「HERO・PC用写真」で写真を選択し、「HERO写真の説明」も更新して保存します。今回指定された写真は **`assets/images/yusuke.gallery_09.jpg`** です。

スマートフォンでも同じ構図を使う場合は、別のモバイル写真を設定する必要はありません。モバイル用写真を指定した場合は、その写真も同じ管理領域から選択します。公開ビルドがHTMLと公開用JSONへ同じ設定を反映するため、HTMLを別途編集しません。

## メンテナンス表示を切り替える

「サイト設定・SNS」の「メンテナンス画面を表示する」をONにして保存すると、公開処理後、TOP・記事詳細を含む各URLがメンテナンス案内になります。更新した通常のTOP画像や記事本文が見えない状態は、この設定がONなら意図どおりです。

**調査開始時点の`main`はONでした。今回の作業ではその設定を維持します。** 通常表示へ再開するときは、内容を確認してOFFにし、保存後の公開成功を確認してください。サーバーを停止したり`404.html`を手で差し替えたりする必要はありません。

既存URLはHTTP 200、存在しないURLはHTTP 404のままです。GitHub Pagesのこの設定からHTTP 503や`Retry-After`を返すことはできません。公開JSON・写真へのアクセス制限でもありません。
