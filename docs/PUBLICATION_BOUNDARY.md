# 公開用ファイルと管理資料の区分

確認日：2026-10-30（日本時間）。GitHub Actionsが生成した `dist/` をGitHub Pagesで配信します。`docs/` を公開フォルダに設定する方式ではありません。

## 二つの公開範囲

| 場所 | Web配信 | Publicリポジトリでの閲覧 | 内容 |
| --- | --- | --- | --- |
| `dist/` のHTML・CSS・JS・アイコン・配信画像 | する | Gitへ通常コミットしないが配信後は保存可能 | 公開ページに必要な内容 |
| `dist/data/` の公開JSON・manifest | する | 配信後は直接取得可能 | 公開記事・プロフィール・許可済みメッセージ・画像寸法やハッシュ等 |
| ソースHTML・`assets/`・`data/` | 必要部分から成果物を生成 | 読める。削除後も履歴に残る | 公開してよいソース・データ・提供画像 |
| `docs/`・`scripts/`・`.pages.yml`・依存/Actions設定 | 成果物の許可リストに入れない | 読める | 秘密を含まない説明・調査・ビルド/復旧手順 |
| プレビュー・ローカルログ・納品ZIP | 公開ワークフローに含めない | 追跡対象へ追加しない | 手元確認・納品の複製。秘密は含めない |
| 回答原文・許諾書・個人連絡先・認証情報・内部調査原本 | しない | リポジトリへ保存しない | 所有者の権限下の別の非公開保管先だけ |

`docs/` はWeb成果物に入らないという意味の非配信資料です。Publicリポジトリ内の文書を、秘密の内部資料とは呼びません。秘密資料は別の非公開ストレージ等へ保存します。

## 画像原本と配信版

原本は `assets/images/`（`uploads/` サブフォルダも含む）に保持し、上書き・一括削除しません。配信版は `dist/assets/optimized/` に生成し、使用する画像だけを対象にします。原本・派生画像の識別、寸法、ハッシュ等は画像manifestで区別します。

原本をWeb成果物から外しても、Publicリポジトリの原本はGitHubから取得できます。原本自体を非公開にする要件がある場合は、リポジトリ公開範囲とCMS保管先を変更する必要があります。

## 公開対象外の記事

`published: false` の記事は公開記事JSON・一覧・詳細HTML・サイトマップへ含めません。ただし元JSONとGit履歴はPublicです。機密の下書きとして秘密を書き込む使い方はできません。

削除した記事は次の公開ビルドから一覧・詳細を除去します。外部キャッシュやGit履歴から即時に消える保証はありません。秘密や個人情報を誤登録した場合は、公開停止と情報に応じた失効・連絡・削除を判断します。

## 成果物を確認する

```bash
.build-venv/bin/python scripts/build.py
.build-venv/bin/python scripts/check_site.py dist
```

先に [ビルド用仮想環境](OPERATIONS.md) を用意し、固定した修正版Pillowを使います。公開・納品前に成果物一覧を確認し、次が入っていないことを確認します。

- `.git`、`.env`、秘密鍵、パスワード、トークン、資格情報入りURL。
- 回答原文、許諾書、個人連絡先、バックアップ、ログ、内部調査原本。
- ビルドスクリプト、ローカル依存、ソースマップ、シンボリックリンク。
- 公開対象外の記事と、使用しない原画像・旧仮画像。

フォルダ・拡張子の許可リストは、秘密が画像や本文へ書き込まれることまで防ぐ仕組みではありません。公開用データの内容も確認します。

## 管理権限との違い

ブラウザーへ渡すコードを完全に隠すことはできません。一方、管理権限・GitHub/CMS認証情報・フォーム回答は利用者へ配信する必要がありません。サービスの権限で守ります。

今回、Public/Private設定、GitHub App権限、Cloudflare/DNS、Google回答共有は変更していません。認証情報をコードへ追加せず、実アカウント設定は所有者が確認します。
