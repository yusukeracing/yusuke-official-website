# 公開コードとセキュリティの範囲

このサイトは GitHub Pages 上で HTML・CSS・JavaScript・画像・公開用 JSON を配信する静的サイトです。問い合わせの受付は Google Forms が担当します。この文書のローカル確認は 2026-10-29 に実施しました。外部サービスへの侵入試験や大量アクセスは行っていません。

## ブラウザーでコードを見られないようにできるか

公開ページの表示に必要な HTML・CSS・JavaScript・画像・JSON は、訪問者のブラウザーへ送信されます。開発者ツール、ページのソース表示、通信内容の保存を完全に禁止することはできません。右クリック禁止、開発者ツールの検出、コードの難読化はアクセス制御にならないため採用しません。

GitHub リポジトリを Private にすると、リポジトリのファイル一覧・履歴へのアクセスを制限できます。ただし、公開サイトに配信するコードは引き続き閲覧できます。Private リポジトリから GitHub Pages を利用できるプランと公開設定を確認してから変更してください。今回はリポジトリの公開範囲を変更していません。

将来、非公開の処理・会員情報・決済を扱う場合は、認証と権限確認を行うサーバー側へ分離します。秘密鍵・管理用トークン・非公開情報を JavaScript に埋め込んで隠す方法は使いません。

## 今の構成で減らしている攻撃面

| 対象 | サイト側で確認できる対策 | 範囲・限界 |
| --- | --- | --- |
| SQLインジェクション | サイトには SQL を実行するサーバー、PHP、データベースがない | このサイトに SQL の実行先がないという意味です。Google Forms の内部実装を検証・保証したものではありません |
| XSS | CMS の文章・企業名などは `textContent` で表示し、HTMLとして実行しない。JSON-LD の `<`・`>`・`&` はビルド時にエスケープする | 検証した入力経路の対策です。GitHub/CMS の書き込み権限を持つ人がサイトのスクリプト自体を変更できる点は別途保護が必要です |
| 不正なURL | `javascript:`・`data:` などの実行用リンクやユーザー名・パスワードを含むURLを拒否。外部リンクは HTTPS を使用 | リンク先サイトの内容・運営の安全性までは保証しません。掲載前に運営者が確認します |
| 外部スクリプト・埋め込み | CSPでスクリプトやiframeの読み込み先を制限。画像は同一オリジンと明示したAnalyticsの接続先に限定し、`base-uri` は `none`。フォームは `https://docs.google.com/forms/.../viewform` のみに限定 | CSP meta はサーバーの不正アクセス防止やアクセス認証の代わりにはなりません |
| 問い合わせ情報 | 送信は Google Forms に任せ、サイトへメール送信キーやDBの接続情報を持たせない | Forms/Sheets の共有範囲、回答受付、通知、保存・削除の設定はフォーム所有者が管理します |
| 配信内容の分離 | 公開用 `dist/` をビルドして配信。既知の7つのJSONと許可した静的ファイルのみを含め、隠しファイル・鍵形式・ソースマップ・シンボリックリンクを除外。`.git`・運用文書・ビルドスクリプトも成果物に含めない | 公開リポジトリ上では、これらのソースや履歴を閲覧できます |
| 公開ワークフロー | 公式 Actions をコミットSHAで固定。ビルドは読み取り、デプロイジョブだけに Pages と ID token の書き込み権限を付与 | GitHubアカウントや外部Appの権限設定は、コードを置くだけでは有効になりません |

将来 SQL を扱うバックエンドを追加する場合は、プレースホルダー付きのパラメーター化クエリ、認証・認可、入力の型・長さの検証、DB最小権限を実装します。文字列の単純な禁止ワード判定やフロント側の入力チェックだけで SQL 対策を済ませません。

## スポンサー・応援メッセージの扱い

`data/` 内の JSON は公開情報です。画面上で非表示にした項目でも、ファイルに含まれていれば直接取得できます。`published: false` などで非公開の回答や個人情報を同じ公開ファイルに保存する運用は行いません。

フォームの回答は Forms/Sheets に保持し、掲載許可を得た企業名・ロゴ・URL、公開用の表示名と応援文だけを CMS へ転記します。メールアドレス、電話番号、送信者の管理情報、未承認の投稿、掲載許可の記録を公開 JSON に入れません。投稿を自動公開する書き込みAPIは設けません。

画像にも位置情報や個人情報が含まれる場合があるため、アップロード前に確認します。今回の確認時点の提供写真19枚には GPS EXIF 情報は検出されませんでした。将来のアップロードについても同じ状態とは限りません。

## 外部サービスで有効にする保護

以下は GitHub・Google・配信基盤の管理画面で設定する内容です。今回は有効化済みとは確認していません。

- GitHub と Google の 2段階認証、可能ならパスキー。編集者・GitHub Apps・CMSの対象リポジトリを必要な範囲に限定する。
- `main` の Ruleset/Branch Protection でレビューと検証を必須にし、force push とブランチ削除を禁止する。CMSの編集は content ブランチから PR で反映する。
- Google Forms/Sheets の回答データを一般公開しない。迷惑送信が発生したら、Google側の公開範囲・回答受付・不正利用対策を確認する。ログインや回数制限を設ける場合は一般の回答者への影響も確認する。
- 独自ドメインと Cloudflare 等を使う場合、WAF、DDoS保護、必要なレート制限とログ監視を配信側で設定する。Google Forms の送信先への迷惑送信は、サイト側のWAFだけでは防げない。
- セキュリティヘッダーを設定できる配信側で、`X-Content-Type-Options: nosniff`、Referrer-Policy、Permissions-Policy、HTTPS確認後のHSTSを設定する。ページ全体を他サイトへ埋め込ませない場合は CSP の `frame-ancestors 'none'` または適切な許可先を HTTP レスポンスヘッダーで設定する。`frame-ancestors` は CSP meta に書いても機能しない。

CloudflareへCSPを追加する場合、HTML内のCSPと両方が適用されます。Google Forms と GA4、JSON-LDのハッシュを含めて整合させ、まずレポート専用設定で確認する方法があります。共通の `unsafe-inline` を足して問題を隠さないでください。詳しい設定・復旧は [運用手順](OPERATIONS.md) を参照してください。

## 今回実施したローカル確認

- CMSの紹介文・経歴・企業名へ `<img ... onerror=...>` を含む文字列を入れ、文字として表示され、画像要素やスクリプトとして追加されないことを確認。
- SQL風の文字列 `' OR 1=1 --` が文字として描画されることを確認。SQL実行先のない構成での表示確認であり、DB侵入試験ではありません。
- `javascript:` のSNS・スポンサーURLがリンクにならないこと、外部ホストのロゴとGoogle以外のフォームURLが読み込まれないことを確認。
- 上記のブラウザ確認では外部通信を禁止し、外部リクエストが発生していないことを確認。問い合わせを送信していません。
- 既存の追跡対象ファイル名に `.env`・鍵ファイル等の公開物がないこと、`assets/`・`data/` にシンボリックリンクがないことを確認。秘密情報の混入を常に防ぐ保証ではないため、公開差分の確認は継続します。

GitHub・Google・Cloudflareへの認証試行、実サイトへの攻撃リクエスト、Google Formsへのテスト回答送信、DDoS耐性試験は行っていません。接続数のローカル測定とその限界は [接続テスト](CAPACITY.md) に記録します。

## 再実行できるブラウザー回帰テスト

開発用のPython PlaywrightとChromiumがある環境で、`python3 scripts/test_public_pages.py --directory dist` を実行します。全11ページの320/390/1440px表示、フォーム設定、公開一覧、攻撃文字列と不正URLを確認します。フォームのHTTP応答はローカルのテスト用データへ置き換え、実際のGoogleフォームへの接続・回答送信は行いません。Google側の公開権限・受付状態はこのテストで検証したものではありません。
