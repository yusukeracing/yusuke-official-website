# セキュリティ確認と対策の範囲

確認日：2026-10-30（日本時間）。対象はリポジトリのソース、公開ビルドの仕組み、到達可能なGit履歴です。公開先への攻撃、管理画面への認証試行、大量アクセスは行っていません。表示・操作テストは [検証記録](VALIDATION.md) を参照してください。

## 公開方式とコードの閲覧

GitHub Actionsで生成した `dist/` をGitHub Pagesへ配信します。`docs/` は説明・調査資料の保存先であり、Pagesの公開フォルダではありません。ただしPublicリポジトリのため、文書、ソース、原画像、Git履歴はGitHubから読めます。詳しくは [公開範囲](PUBLICATION_BOUNDARY.md) を参照してください。

HTML・CSS・JavaScript・配信画像・公開JSONは利用者のブラウザーへ送るため、保存・閲覧できます。これは管理権限を取得して改ざんすることとは別です。右クリック禁止や難読化をアクセス制御として扱いません。

## 実施した確認

| 対象 | 確認結果 | 範囲・限界 |
| --- | --- | --- |
| 追跡ファイル名 | `.env`、秘密鍵、SQLダンプ、バックアップ、ログ等の疑わしい追跡名なし | 任意の名前のファイルをすべて機密判定する検査ではない |
| Git履歴 | 作業開始時の到達可能350オブジェクト中、2MB以下・NULなしの213テキストblobを検査。秘密鍵、GitHub Token、AWSアクセスID、Google APIキー、Slack Tokenの高確度パターン該当なし | 非到達オブジェクト、外部ログ、任意形式のパスワード、暗号化データは対象外 |
| 接続先 | `origin` のURLにユーザー名・パスワードの埋め込みなし | GitHub側のアカウント・App権限は別確認 |
| 位置情報 | 追加写真を含む提供実写真20ファイルでGPS EXIFタグを検出せず | 写り込みの内容や、新しいアップロードの同意・個人情報は別確認 |
| 資産・データ | `assets/`・`data/` にシンボリックリンクなし。公開用の許可リストから成果物を生成 | 許可された画像・文章へ人が秘密を記入することまでは防げない |
| 公開処理 | 公式Actionsを完全なコミットSHAで固定。ビルドは `contents: read`、公開ジョブだけ `pages: write` と `id-token: write`。チェックアウトの資格情報を残さない | 所有者によるGitHubの保護設定は別途必要 |

この確認で流出した認証情報として報告すべき値は検出していません。将来秘密情報が見つかった場合は、削除だけでなく発行元で失効・再発行します。Git履歴の書き換えだけで秘密を回収できたとは扱いません。

## 入力と外部通信

| 経路 | 対策と確認の範囲 |
| --- | --- |
| CMSの本文・説明・代替テキスト | HTMLとして解釈せず、ビルドはエスケープ、ブラウザーは `textContent` 等で描画。サイトのHTML・JS自体の編集権限は別に守る |
| 写真・サムネイル | 許可したローカル画像パスと寸法を検証。公開用の画像へ変換し、実行用URL・任意の外部画像を採用しない |
| リンク | `javascript:`、資格情報入りURL等を拒否。外部リンクはHTTPS、別タブは `noopener noreferrer`。リンク先の内容までは保証しない |
| JSON-LD | `<`・`>`・`&` をデータとしてエスケープし、CSPハッシュを再生成。`unsafe-inline` で回避しない |
| Google Forms | `https://docs.google.com/forms/.../viewform` を検証。回答受付・認証条件・受信・通知・回答共有は所有者が確認する |
| GA4 | 公開用測定IDが設定された場合のみGoogleの計測スクリプトを読む。APIシークレットやサービスアカウント鍵は配信しない |

静的サイト内にPHP、DB、SQL実行処理はありません。このサイトにSQLを実行する入口がないことと、外部サービスが攻撃されないことは同義ではありません。将来バックエンドを追加する場合は、その実装で認証・認可・パラメーター化クエリ等を設けます。

## 下書きと個人情報

記事の公開スイッチはWeb成果物への掲載を切り替えるものです。公開対象外の記事を配信用JSON・一覧・詳細から除外しても、Publicリポジトリの元JSONとGit履歴からは読めます。機密の下書き機能ではありません。

Formsの回答原文、メール・電話、未承認投稿、許諾記録、内部調査原本、認証情報はこのリポジトリ・納品ZIPへ保存しません。掲載するのは公開してよい表示名・承認済み本文等だけです。回答を自動でサイトへ投稿するAPIは設けていません。

## CSPと実際に使えるヘッダー

コードで確認できるのはHTMLのCSP metaとreferrer metaです。自己オリジンの資産、明示したForms・GA4等だけを許可し、`object-src 'none'`、`base-uri 'none'` を使います。任意の外部スクリプトをCMSから追加する仕組みはありません。

GitHub Pagesでは、`_headers` や `.htaccess` を置くだけで任意のHTTPヘッダーを設定できません。そのようなファイルを対策済みの根拠として追加しません。`frame-ancestors` はCSP metaでは機能しません。

`X-Content-Type-Options`、`Permissions-Policy`、HSTS、HTTPヘッダーによる埋め込み元制限は、対応する配信基盤で設定し、実レスポンスを確認した場合にのみ有効化済みとします。Cloudflareの導入・DNS・ルールは今回変更していません。本番HTTP読み取りは環境の通信プロキシで403となり、実ヘッダー・HTTPS証明書を確認済みとはしていません。

## 依存関係

ブラウザー側はHTML・CSS・Vanilla JavaScriptで、外部フロントエンドライブラリ・Webフォントを追加していません。フォントは端末のシステムフォントです。SVGアイコン・商標の記録は [アイコンの説明](../assets/icons/README.md) を残しています。

画像の配信版生成にPillowをビルド時だけ使用し、出荷用の固定値を `Pillow==13.0.0` へ変更しました。Pillow本体はWeb成果物へコピーしません。依存ライセンスと原文は [第三者素材・依存の記録](../THIRD_PARTY_NOTICES.md) と `licenses/` に保持します。実際の導入・再ビルド・回帰確認の結果は検証記録と分けて記録します。

## Pillowの公式アドバイザリ確認と対処

この依存は今回追加する配信用画像ビルドで導入するものです。調査開始時の公開サイトがPillowをブラウザーへ配信していたという判定ではありません。初期のローカル検証に使った12.3.0は最終ビルドへ使わず、13.0.0へ更新しました。

2026-10-30（日本時間）、公式GitHubのアドバイザリ一覧、リリース一覧、次の個別アドバイザリをHTTP 200で読み取りました。[機械可読の確認記録](sources/pillow-advisory-check.json) にURL・影響範囲・修正版を保存しています。

| 項目 | 公式資料に記載された内容 |
| --- | --- |
| アドバイザリ | [GHSA-78g4-xqwv-q3g8](https://github.com/python-pillow/Pillow/security/advisories/GHSA-78g4-xqwv-q3g8) |
| 公開日・深刻度 | 2026-10-17公開、High、CVSS 8.1 |
| 影響バージョン | 11.1.0～12.3.0 |
| 修正版 | 13.0.0 |
| 問題 | 同梱OpenJPEGによるJPEG 2000のデコードでヒープバッファーオーバーフロー書き込み。`Image.open()` と画像の読み込み処理から到達する |
| 修正版の公開確認 | [公式リリース一覧](https://github.com/python-pillow/Pillow/releases)に13.0.0を確認 |

以前の固定値12.3.0は、この明示された影響範囲に含まれます。単に新しいバージョンがあるためではなく、この公式の影響・修正情報を根拠に13.0.0へ変更しました。12.3.0のままでの出荷は行わず、13.0.0の導入、再ビルド、回帰テストを公開前の確認対象とします。

追加対策として、画像を開く際にJPEG・PNG・WebP・AVIFのデコーダーへ限定し、検出した形式と拡張子を照合します。Pillowは拡張子だけでなく画像の内容から形式を検出するため、ファイル名だけの制限では十分ではありません。

この問題の評価対象は画像を処理するビルド環境です。Pillowをブラウザーへ配信する構成ではなく、サイトのHTML・JavaScriptで画像デコーダーが実行されるという意味ではありません。提供された写真原本20ファイルは変更せず、悪性画像だという証拠も見つかっていません。

今回の確認は公式GitHubの3ページに限ります。NVD等の外部脆弱性データベースを網羅した監査ではなく、「すべてのCVEがゼロ」「未知の脆弱性がない」と保証するものではありません。

## 管理権限

所有者はGitHub・CMS・Googleの2段階認証やパスキー、復旧手段、不要な編集者・App権限の削除を管理します。CMSの対象はこのリポジトリに限定します。PR必須・force push禁止等のGitHub保護設定は、ファイルだけで有効にはなりません。CMSの保存方式と両立するルールを選びます。

改ざん時は [対応テンプレート](INCIDENT_RESPONSE.md) に沿って証跡保全、公開判断、失効、復旧、再確認を行います。静的配信・CSP・最小権限はリスクを減らしますが、絶対に攻撃・改ざんされないとの保証はしません。
